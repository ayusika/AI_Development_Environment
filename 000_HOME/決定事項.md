# Koppy

- KoppyはAI開発環境全体の人格・対話・判断の中枢とする。
- DNAはKoppyの根幹であり、Version 1.0以降は安易に変更しない。
- Koppy設計書はDNAとは別管理とし、成長可能な仕様を記述する。

---

# AIチーム

- AIチームはKoppyとは別人格ではなく、専門AIチームとして運用する。
- CodexはAIチーム最初のメンバーとする。
- Codexはコード・Markdown・検索・比較・調査を担当する。
- AIチームは今後増員可能とする。
- AIチームはKoppyの代読者にはしない。
- Koppy自身が原文を直接確認し、AIチームは調査・分析・実装を支援する。

# Snapshot

- Snapshotを完成形までの仮設橋として採用する。
- Snapshotはプロジェクト全体の「その瞬間の世界」を保存する。
- Gitは履歴管理、Snapshotは世界全体の保存という役割で使い分ける。
- Snapshotファイル名は以下とする。

AI_Development_Environment_Snapshot_vYYYY-MM-DD_HH-MM.zip

- Snapshotは「Koppy World Snapshot」として運用する。
- Snapshot生成コマンドはユーザー辞書に登録する。
- ユーザー辞書の読みは「こぴすな」とする。

# 開発方針

- 便利さよりも継続性・保守性を優先する。
- 一度決めた設計は安易に変えず、必要な場合のみVersionを更新する。

## 2026-08-09｜000_HOME Writer書き込み権限

KoppyOSの「セーブ！」運用で使用するため、Writerから以下の4ファイルへのGitHub書き込みを許可する。

- `000_HOME/決定事項.md`
- `000_HOME/現在の状態.md`
- `000_HOME/更新履歴.md`
- `000_HOME/次にやること.md`

### 決定

`000_HOME/` ディレクトリ全体にはWriter権限を与えない。

上記4ファイルのみをExact Match Allowlistとして許可する。

これにより、KoppyOSの現在地・決定事項・更新履歴・次アクションをWriter Proposal経由で保存できるようにしつつ、000_HOME内のその他のファイルへの不要な書き込み権限拡大を防ぐ。

GitHubへの実書き込みは従来どおり、

Proposal
→ Approval
→ Execute

の承認フローを維持する。

## 2026-09-08｜Writer / Codex Dual Executor正式採用

KoppyOSの標準開発フローとして、
WriterとCodexを異なる役割を持つExecutorとして併用する
Dual Executor構成を正式採用する。

### 基本役割

Koppyは、
設計・判断・仕様決定・Executor選択を担当する。

Writerは、
Koppyが確定した変更を正確に反映する
Deterministic Executorとして扱う。

Codexは、
ローカル実ファイルを確認し、
決定済みの仕様・制約・成功条件をもとにコードを実装する
Intelligent Code Executorとして扱う。

### Executor Mode

標準モードとして、

- AUTO
- WRITER
- CODEX

の3モードを採用する。

ユーザーがExecutorを指定しない場合はAUTOとし、
Koppyが作業内容を判断してWriterまたはCodexを選択する。

ユーザーがWriterまたはCodexを明示指定した場合は、
原則としてその指定を優先する。

ただし、
安全性または合理性に重大な問題がある場合は、
Koppyが代替Executorを提案できる。

最終判断はユーザーが行う。

### Writer優先対象

以下は原則としてWriterを優先する。

- 設計思想
- 運用ルール
- 現在地
- 次にやること
- 決定事項
- 更新履歴
- 引き継ぎ情報
- セーブ処理
- 小規模で変更内容が完全に確定しているExact Match編集

`セーブ！` によるKoppyOS状態確定は、
原則Writerで行う。

### Codex優先対象

以下は原則としてCodexを優先する。

- HTML
- CSS
- JavaScript
- PHP
- その他のプログラムコード
- 複数ファイル実装
- リファクタリング
- コード構造解析
- テスト
- diff確認
- Git操作を伴う開発

Codexは未確定仕様を独自判断で確定しない。

### Protocol

Executor選択の正式ルールは、

`600_KoppyOS/protocols/EXECUTOR_SELECTION_PROTOCOL.md`

を正本とする。

ファイル編集時の安全原則は、

`600_KoppyOS/protocols/FILE_EDIT_PROTOCOL.md`

を正本とする。

役割は以下のように分離する。

```text
EXECUTOR_SELECTION_PROTOCOL
↓
どのExecutorを使用するか決定

FILE_EDIT_PROTOCOL
↓
選択されたExecutorが
どのように安全にファイルを変更するか定義
```

### Codex Repository Guide

リポジトリルートの

`AGENTS.md`

をCodex用の入口・地図として採用する。

AGENTS.mdは巨大な仕様書にせず、
詳細情報を各GitHub正本へ誘導する短いガイドとして維持する。

不足するCodexルールが判明した場合のみ、
段階的に追加・拡張する。

### Writer target_path

Writer APIへ渡す対象ファイルパスは、
repository nameを含めない
repo-relative pathを正式形式とする。

正：

```text
600_KoppyOS/protocols/FILE_EDIT_PROTOCOL.md
```

誤：

```text
AI_Development_Environment/600_KoppyOS/protocols/FILE_EDIT_PROTOCOL.md
```

人間向け表示パスと、
Writerへそのまま入力する実データは分離して扱う。

### 基本原則

KoppyOSでは、

```text
Koppy = 考える
Writer = 決めた変更を正確に反映する
Codex = 実装を理解してコードを変更する
```

を基本とする。

WriterとCodexは競合させず、
作業内容に応じて使い分ける。

## 2026-09-08｜VS Code Agent Executor正式採用

KoppyOSの正式Executorとして、
VS Code Agentを追加採用する。

VS Code Agentは、

Intelligent Local Workspace Executor

として扱う。

### 基本役割

VS Code Agentは、
VS Codeからアクセス可能なローカルworkspace・実ファイル・Terminalを使用し、
Koppy / ユーザーが確定した仕様・制約・成功条件をもとに作業する。

主な対象：

- VS Code workspace内のコード編集
- ローカルファイルの作成・編集・削除
- 複数ファイル実装
- Terminalコマンド実行
- テスト・lint・動作確認
- diff / Git状態確認
- Git管理外ローカルファイル
- macOS上で利用可能なiCloud Drive同期ファイル
- Codex利用不能時のコード作業fallback

VS Code Agentは、
Koppyの代わりに未確定仕様を決定しない。

### Executor Mode

KoppyOSの標準モードを以下の4つとする。

```text
AUTO
WRITER
CODEX
VSCODE_AGENT
```

AUTOでは、
Koppyが作業内容・対象環境・安全性を判断してExecutorを選択する。

通常のコード開発ではCodexを第一候補とする。

ただし、

- Codexが利用できない
- VS Code workspace内で直接作業する方が合理的
- Git管理外ローカルファイルを扱う
- iCloud Drive等の同期ローカルファイルを扱う
- ローカルTerminal実行との連携が適している

場合は、
VSCODE_AGENTを選択できる。

### Fallback

通常のコード作業におけるfallbackは、

```text
CODEX
↓
VSCODE_AGENT
↓
WRITERで安全に代替可能か判定
↓
安全に代替できなければSTOP
```

を基本とする。

ただし、
ユーザーがExecutorを明示指定している場合は、
無断で別Executorへ切り替えない。

Koppyは代替案を提示し、
最終判断はユーザーが行う。

### Intelligent Executor共通安全ルール

Codex / VS Code Agentでは、
以下を共通安全ルールとする。

- 実ファイルを確認してから変更する
- Git管理対象ではgit statusを確認する
- 必要に応じてorigin/mainとの差分を確認する
- unrelated filesを変更しない
- Minimum Safe Changeを優先する
- force pushを行わない
- conflictを勝手に解決しない
- 不明な仕様を推測して確定しない
- ユーザーが禁止した操作を行わない
- 必要なruntime / toolが存在しない場合、勝手にインストールしない
- OS・アプリ・権限・環境設定を無断変更しない
- 安全に継続できない場合はSTOPする

### iCloud Drive

VS Code Agentについて、
macOS上でローカルファイルとして利用可能な
iCloud Drive同期領域への読み書きを実機確認した。

ただし、
iCloud Drive全体へ無条件にアクセス可能とみなさない。

実作業では毎回、

- 実パス
- 対象ファイル
- 親ディレクトリ
- 同期状態
- アクセス可能状態

を確認してから変更する。

### 実機確認済み能力

2026-09-08のテストで以下を確認した。

- KoppyOS正本の参照
- Git状態確認
- ローカルファイル作成
- 既存ファイル編集
- Terminal実行
- 実行結果確認
- 問題検出後の自己修正
- Safe STOP
- テストファイルの安全な削除
- iCloud Drive同期領域での作成・読込・削除
- 既存ファイル不変性の確認

### Protocol

正式ルールは、

```text
600_KoppyOS/protocols/EXECUTOR_SELECTION_PROTOCOL.md
```

を正本とする。

VS Code Agent追加後のVersionは、

```text
v0.2
```

とする。

### 基本原則

KoppyOSでは、

```text
Koppy = 考える
Writer = 決めた変更を正確に反映する
Codex = 実装を理解してコードを変更する
VS Code Agent = ローカルworkspaceと実環境を使って作業する
```

を基本とする。

Writer / Codex / VS Code Agentは競合させず、
作業内容と実行環境に応じて使い分ける。
