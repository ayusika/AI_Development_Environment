## 2026-08-09｜Writer長文Transport・セーブ経路更新

### Writer Adaptive Chunk Transport

Koppy World WriterへAdaptive Chunk Transportを統合。

通常のProposal送信がWAFによってHTTP 403となった場合、自動的にAdaptive Chunk Transportへフォールバックする構成とした。

長文をBase64へ変換して分割し、WAFを通過できないChunkのみをさらに再分割する。

全Chunk送信後はサーバー側で再結合し、SHA-256による完全性検証を行ってからProposalを生成する。

本番Koppy WorldのWriter UIから長文Proposalを作成し、DevToolsによる手動分割・送信なしで正常完走することを確認した。

### Koppy World UI Deploy

`900_Lab/Web_KoppyOS_Beta/index.html`

を

`/koppy/index.html`

へDeployするExact Match AllowlistをDeploy系APIへ追加。

Koppy World UI自身をProposal → Approval → Execute経路で本番反映できるようにした。

### 000_HOME Writer権限

以下4ファイルをWriterのExact Match Allowlistへ追加。

- `000_HOME/決定事項.md`
- `000_HOME/現在の状態.md`
- `000_HOME/更新履歴.md`
- `000_HOME/次にやること.md`

これにより「セーブ！」で使用するKoppyOS運用情報をWriter Proposal経由でGitHubへ保存できる基盤が開通した。

## 2026-09-07｜Kohaku Work 確定済み売上修正・予約再計算 完成

Kohaku Workの確定済み売上について、
確定後の訂正を安全に行うための機能を実装し、
本番実地テストまで完了した。

### 確定済み売上の手動修正

確定済み売上で以下を修正可能にした。

- チップ
- 値引き
- 値引き理由
- 値引きメモ
- 調整額

確定時のコース・OP・指名料snapshotは維持したまま、
顧客支払額と手取り合計を再計算する。

変更前後は
`visit_sales_history`
へ保存する。

### 確定済みsnapshotの固定表示

確定済み売上は、
現在の予約内容や料金マスタから再計算せず、
確定時に保存したsnapshotを表示の正本として使用するよう整理した。

これにより、
予約や料金マスタを後から変更しても
過去の確定済み売上が意図せず変化しない。

### 予約内容から売上を再計算

確定後に予約内容自体の誤りが判明した場合に備え、

`予約内容から売上を再計算`

機能を追加した。

予約側で訂正した以下の内容から
確定済み売上snapshotを再作成できる。

- コース
- 延長
- OP
- 指名料

以下は既存の確定値を維持する。

- チップ
- 値引き
- 値引き理由
- 値引きメモ
- 調整額
- confirmed_at

再計算前後の売上データは
`visit_sales_history`
へ保存する。

### Backend

主な変更：

- `koppyCalculateVisitSales()`
  - 確定済みsnapshot固定表示
  - 予約再計算用の内部モード追加

- `koppyRecalculateConfirmedVisitSales()`
  - 現在予約から新snapshotを作成
  - Transaction内で売上更新
  - 変更履歴保存
  - confirmed_at維持

- `visit-sales.php`
  - `mode: recalculate` を追加
  - `revise` と同様にTransaction経路で処理

### Frontend

確定済み売上へ以下の操作を追加。

- `売上を修正`
- `予約内容から売上を再計算`

再計算前には確認ダイアログを表示し、
成功後は最新の確定済み売上を再取得する。

### 本番確認

- 調整額修正後の合計更新：PASS

## 2026-09-08｜KoppyOS Writer / Codex Dual Executor導入

KoppyOSの開発・正本更新フローへ、
WriterとCodexを異なる役割で使用する
Dual Executor構成を導入した。

### Executor Selection Protocol

以下を新規作成。

`600_KoppyOS/protocols/EXECUTOR_SELECTION_PROTOCOL.md`

AUTO / WRITER / CODEXの3モードを定義し、
ユーザーがExecutorを指定しない場合は、
Koppyが作業内容に応じてExecutorを選択する構成とした。

### File Edit Protocol接続

`600_KoppyOS/protocols/FILE_EDIT_PROTOCOL.md`

へExecutor Selection Protocolとの役割分担を追加。

Executor Selection Protocolが
「どのExecutorを使用するか」を決定し、

File Edit Protocolが
「選択されたExecutorがどのように安全にファイルを変更するか」
を定義する構成とした。

### Writer / Codex役割分担

Writerは、
確定済み変更を正確に反映する
Deterministic Executorとして運用する。

Codexは、
ローカル実ファイルを確認してコードを実装する
Intelligent Code Executorとして運用する。

設計判断・仕様決定・Executor選択は
Koppy / ユーザー側で行う。

### Koppy OS表示ルール

`040_Koppy/性格/README.md`

へExecutor別表示ルールを追加。

Writerでは、
変更対象・操作・理由・Exact Match等を
個別に安全コピーできる形式を使用する。

Codexでは、
置換コードを事前生成するのではなく、
目的・要件・禁止事項・確認項目等を含む
完全な実装指示を渡す方式とした。

### Writer target_path修正

Writer API / Executorへ渡す対象パスを、
repository nameを含まない
repo-relative pathへ統一した。

これにより、
`AI_Development_Environment/` を含むパスによって
Writer Allowlistが403となる不整合を解消した。

### Codex Repository Guide

リポジトリルートへ

`AGENTS.md`

を新規作成。

Codexが作業開始時に読む短い入口・地図として使用し、
詳細仕様は既存のGitHub正本へ誘導する構成とした。

### Codex Git動作確認

Codexについて以下を確認済み。

- ローカルrepository読込
- ファイル編集
- git status / diff
- commit
- non-fast-forward検知
- fetch / rebase
- normal push
- GitHub正本反映
- Koppyによる再読込

force pushは禁止し、

### コピペ完全性ルール強化

Writerへ渡すMarkdown本文内部にコードフェンスが存在する場合、
外側のコピー用コードフェンスと衝突して

対策として、

「コピー対象内部で使用されている最長コードフェンスより

`040_Koppy/性格/README.md`
へ追加した。

これにより、

## 2026-09-08｜KoppyOS VS Code Agent Executor正式採用

Codexの利用上限を契機として、
VS Code AgentがKoppyOSの代替・補完Executorとして安全に利用できるか実機検証を行った。

検証結果を受け、
VS Code Agentを正式に

`Intelligent Local Workspace Executor`

としてKoppyOSへ追加した。

### Executor Selection Protocol更新

`600_KoppyOS/protocols/EXECUTOR_SELECTION_PROTOCOL.md`

をv0.2へ更新。

標準Executor Modeを、

```text
AUTO
WRITER
CODEX
VSCODE_AGENT
```

の4モード構成とした。

### VS Code Agentの役割

VS Code Agentは、
VS Codeからアクセス可能なローカルworkspace・実ファイル・Terminalを使用して作業する。

主な用途：

- VS Code workspace内のコード編集
- ローカルファイル作成・編集・削除
- 複数ファイル実装
- Terminalコマンド実行
- テスト・lint・動作確認
- diff / Git状態確認
- Git管理外ローカルファイル操作
- macOS上で利用可能なiCloud Drive同期ファイル操作
- Codex利用不能時のコード作業fallback

### ローカルExecutor実機テスト

VS Code AgentへKoppyOS正本参照を含むテスト指示を渡し、
以下を確認した。

- `AGENTS.md`参照
- `EXECUTOR_SELECTION_PROTOCOL.md`参照
- `FILE_EDIT_PROTOCOL.md`参照
- git status確認
- branch確認
- origin/mainとの差分確認
- ローカルファイル作成
- 既存ファイル再読込
- 既存ファイル編集
- Terminal実行
- 実行結果検証
- 問題検出後の自己修正
- unrelated files無変更
- commit / push禁止指示の遵守

### Safe STOP確認

初回の実行テストでは、
ローカル環境にNode.jsが存在しなかった。

VS Code Agentは、
Node.jsを勝手にインストールせず、
安全に続行できないとしてSTOPした。

この結果を受け、
Codex / VS Code Agent共通のIntelligent Executor安全ルールとして、

- 必要runtime / toolを勝手にインストールしない
- OS・アプリ・権限・環境設定を無断変更しない
- 安全に継続できない場合はSTOPする

を正式化した。

