## 2026-08-08｜Koppy Server Deploy v1 完成

Koppy Server APIについて、
GitHub正本からロリポップ本番サーバーへ安全に反映する
承認付きDeploy経路を構築し、実機検証まで完了した。

### Deployフロー

GitHub正本
→ Deploy Proposal作成
→ しいちゃんによる明示承認
→ Executor実行
→ 一時ファイルへ配置
→ SHA-256照合
→ 本番ファイルへAtomic Replace
→ 配置後のhash / size再検証
→ Deploy Log保存

### 実装済み

- `deploy/proposal.php`
- `deploy/approve.php`
- `deploy/executor.php`
- Deploy対象パスのAllowlist
- Protected Files拒否
- Commit SHA Binding
- Deploy前バックアップ
- 一時ファイルによる事前検証
- Atomic Replace
- 配置後hash / size検証
- Deploy Proposal / Log / BackupのGitHub外保存

秘密情報およびDeploy管理データは、
Server上の `.koppy-private/` を利用する。

### ロリポップ環境への対応

ロリポップ環境では、
PHP CLIによるsyntax checkが `Permission denied` となることを実機で確認した。

そのためDeploy v1では、
PHP syntax checkを実行可能な場合のみ追加検証として利用する。

サーバー制約による `Permission denied` の場合は
Deployを失敗させず、

`syntax check unavailable`

として記録する。

hash / size検証は引き続き必須とする。

### 実機卒業試験

テスト用PHPファイルをGitHub正本からDeployし、
以下を確認した。

- Proposal作成成功
- 明示承認成功
- Executor実行成功
- `status: executed`
- `verification.passed: true`
- `hash_matches: true`
- `size_matches: true`
- 実URLから `KOPPY_DEPLOY_V1_SUCCESS` を確認

試験終了後、
テスト用 `KOPPY_DEPLOY_TEST.php` は
GitHub正本・ロリポップ本番サーバーの双方から削除。

公開URLが404になることまで確認した。

### 運用上の到達点

Koppy Worldフロント：

GitHub Actions Auto Deploy

Koppy Server API：

承認付き Koppy Server Deploy v1

を今後の標準Deploy経路とする。

これにより、
通常の開発・更新における
Cyberduck手動Upload運用を卒業した。

Cyberduckは今後、

- 障害対応
- 緊急復旧
- GitHub Deploy経路外の特殊作業

など、必要時のみ利用する。

### Deploy v1の現在の制約

GitHub正本から削除されたファイルを、
ロリポップ本番サーバーから自動削除する機能は
Deploy v1にはまだ存在しない。

今回の卒業試験でも、
テストファイルの本番サーバー側削除のみ
Cyberduckで手動実施した。

安全な削除Deployについては、
将来のDeploy v2候補として扱う。

## 2026-08-09｜KoppyOS Writer長文Transport・000_HOME書き込み経路 開通

### Writer Adaptive Chunk Transport

Koppy World WriterへAdaptive Chunk Transportを統合し、本番環境で長文Proposal生成が成功した。

通常の `brain/proposal.php` への送信がWAFによってHTTP 403となった場合でも、Writerが自動的にAdaptive Chunk Transportへフォールバックする。

確認済みフロー：

Writer
→ 通常Proposal送信
→ WAF 403検出
→ Adaptive Chunk Transportへ自動切替
→ Base64分割
→ WAFを通過できないChunkのみ再分割
→ 全Chunk送信
→ Finalize
→ Base64再結合
→ SHA-256完全性検証
→ Proposal生成

DevToolsによる手動分割・送信を行わず、Koppy WorldのWriter UIのみで長文Proposal生成まで完走することを本番確認済み。

### 000_HOME Writer権限

Writerから以下の4ファイルへの書き込みをExact Matchで許可した。

- `000_HOME/決定事項.md`
- `000_HOME/現在の状態.md`
- `000_HOME/更新履歴.md`
- `000_HOME/次にやること.md`

`000_HOME/` ディレクトリ全体には書き込み権限を与えず、上記4ファイルのみを許可する。

これにより、KoppyOSの「セーブ！」運用から、現在地・決定事項・更新履歴・次アクションをWriter Proposal経由でGitHubへ保存できる基盤が整った。
