## 2026-08-08｜Koppy World Auth v1 完成

Koppy WorldのGitHub認証基盤 Auth v1 が完成し、実機検証まで完了。

### 実装済み

- GitHub App「Koppy World Auth」を作成
- GitHub OAuthによるログイン
- GitHub User Allowlistによる利用者制限
- 認証Sessionの生成・確認
- Koppy WorldフロントのAuthentication Gate
- 未認証時はKoppy World本体を表示せずGitHubログインへ誘導
- API共通 `bootstrap.php` にServer-side Authentication Guardを実装
- 認証済みSessionのみ保護APIへのアクセスを許可
- Session idle timeoutを実装

### 実機検証

認証済み通常ブラウザ：

- Koppy World表示成功
- Brain API取得成功

未認証シークレットブラウザ：

- Front Authentication Gate表示成功
- `brain/github.php` → `Authentication required.`
- `brain/proposal.php` → `Authentication required.`
- `brain/approve.php` → `Authentication required.`
- `brain/executor/github.php` → `Authentication required.`

以上により、

GitHub OAuth
→ User Allowlist
→ Session
→ Front Authentication Gate
→ Server-side Authentication Guard
→ Protected API

までの認証経路が正常に接続されていることを確認した。

### Writer書込境界

Koppy WriterのGitHub書込先はAllowlist方式で制限する。

現在の許可領域：

- `600_KoppyOS/`
- `900_Lab/`

Allowlist外は、Proposalが承認済みであってもExecutor側で拒否する。

`000_HOME/` は現在Writerの書込許可対象外とし、
設計上の重要領域として手動更新を継続する。

### セキュリティ上の暫定事項

ロリポップWAFがKoppy WriterからのPOSTリクエストを403で遮断したため、
`koppy.miki-piano.com` のWAFを現在無効化している。

これは恒久設定とはせず、
Koppy WorldのAPI設計が安定した段階でWAF再有効化または代替防御を検討する。

### 現在地

## 2026-08-08｜Koppy World 同一ドメイン移住・秘密鍵ローテーション完了

Koppy WorldをGitHub Pages上の公開フロントから、
`koppy.miki-piano.com` 上で動作する同一ドメイン構成へ移行した。

### 移行理由

GitHub Pages版Koppy World：

`https://ayusika.github.io/AI_Development_Environment/`

から、

Koppy API：

`https://koppy.miki-piano.com/api/`

へSession Cookie付きで通信する構成では、
ブラウザのCross-Site Cookie制限により、
直接 `session.php` を開くと認証済みでも
Koppy World側のfetchでは未認証として扱われる問題が発生した。

この問題を避けるため、
Koppy World本体とKoppy APIを同一ドメインへ統合した。

### 現在の実働構成

Koppy World：

`https://koppy.miki-piano.com/`

Koppy API：

`https://koppy.miki-piano.com/api/v1/`

Server上：

`/home/users/2/her.jp-mikipiano/web/koppy/`

構成：

- `index.html`
- `api/`

### 実機確認

同一ドメイン移行後、以下を確認済み。

- Koppy World表示成功
- GitHub Authentication Gate正常動作
- GitHub OAuthログイン成功
- PHP Session保持成功
- GitHub Brain取得成功
- Koppy ChatからOpenAI API応答成功
- Server-side Authentication Guard正常動作

### 秘密鍵ローテーション

LINEメモ等に保管していた秘密情報について、
漏洩可能性を考慮してローテーションを実施した。

完了：

- OpenAI API Keyを新規発行
- Koppy Serverの `.koppy-private/config.php` を新Keyへ更新
- 新OpenAI API KeyでKoppy Chat実働確認
- 旧OpenAI API Keyを失効

- GitHub App「Koppy World Auth」のClient Secretを新規発行
- `.koppy-private/auth-config.php` を新Secretへ更新
- 新Client SecretでGitHub OAuth実働確認
- 旧Client Secretを失効

以後、
API Key / Client Secret / Token等の秘密情報は
LINE・チャット・GitHubへ保存しない。

秘密情報はGitHub外の
`.koppy-private/`
をServer実働用の保管領域として継続利用する。
